Atelier Pipeline – Étude de cas 1

Atelier 1 : Ingestion dynamique multi-sources avec validation

Contexte : Optimisation d'une chaîne d'approvisionnement en énergie renouvelable

Une usine de production traditionnelle décide de migrer vers un modèle hybride solaire-éolien. Les données énergétiques proviennent de multiples capteurs et systèmes (consommation actuelle, production solaire, production éolienne, stockage batteries).

1. État des lieux

  • 3 sources de données quotidiennes :
  • besoins_energetiques.csv (consommation horaire de l'usine)
  • production_solaire.csv (rendement des panneaux par zone)
  • production_eolienne.csv (données des turbines)
  • Dépôt non structuré : fichiers déposés manuellement dans un dossier
  • Absence de validation : impossible de savoir si toutes les sources sont arrivées
  • Processus manuel : un technicien vérifie et importe les fichiers dans Excel

2. Problématique

Comment automatiser l'ingestion de données énergétiques hétérogènes pour analyser les besoins actuels et identifier les sources renouvelables disponibles, sans intervention manuelle et avec validation de la complétude ?

Contraintes :

  • ✅ Détecter dynamiquement quels fichiers sont présents
  • ✅ Ignorer les fichiers non-CSV (logs techniques, images...)
  • ✅ Créer une table Bronze par source énergétique
  • ✅ Tracer les fichiers ingérés pour l'audit

3. Solution : Pipeline d'ingestion intelligent

Pipeline qui scanne, filtre, copie et trace automatiquement toutes les sources énergétiques vers Bronze.

10. Ajouter les activités de traçabilité (dans la branche True)

Toujours dans la branche True, après CopierVersBronze, il faut ajouter deux activités pour tracer les fichiers traités.

Activité 1 : TracerFichier (Append Variable)

  1. Activities → General → glissez Append Variable sur le canvas

  3. Cliquez sur Append Variable

  4. Onglet General :

  • Name : TracerFichier
  1. Onglet Settings :
  • Variable name : sélectionnez FichiersTemp
  • Value : cliquez Add dynamic content
  • Copiez-collez :

@item().name

  • Cliquez OK

💡 Astuce : On accumule dans FichiersTemp car Fabric interdit à une variable de se référencer elle-même — c'est la variable tampon intermédiaire.

Activité 2 : RecupererTracage (Set Variable)

  1. Activities → General → glissez Set Variable sur le canvas

  2. Reliez TracerFichier → RecupererTracage (flèche verte)

  3. Cliquez sur Set Variable

  4. Onglet General :

  • Name : RecupererTracage
  1. Onglet Settings :
  • Variable name : sélectionnez FichiersTraites
  • Value : cliquez Add dynamic content
  • Copiez-collez :

@variables('FichiersTemp')

  • Cliquez OK

💡 Astuce : RecupererTracage recopie l'état actuel de FichiersTemp dans FichiersTraites à chaque itération. À la fin de la boucle, FichiersTraites contient la liste complète des fichiers traités.

⚠️ Pourquoi deux activités ? Fabric interdit l'expression @union(variables('FichiersTraites'), array(item().name)) dans un Set Variable car la variable ne peut pas se référencer elle-même (self-referencing variable error). Le pattern FichiersTemp → FichiersTraites contourne cette limitation.

Question 1 : Validation de la complétude des sources

La variable FichiersTemp accumule via Append Variable, puis RecupererTracage recopie l'état dans FichiersTraites. Le résultat final :

["besoins_energetiques.csv", "production_solaire.csv", "production_eolienne.csv"]

Impact métier : Si un fichier manque demain (ex: production_solaire.csv), la variable NombreFichiers serait = 2 au lieu de 3, ce qui déclencherait une alerte.

Question 2 : Granularité temporelle des besoins énergétiques

Analysez la table besoins_energetiques :

SELECT COUNT(*) as NbReleves FROM besoins_energetiques
-- Résultat : 168 lignes

Calculez la fréquence de mesure :

168 relevés sur 7 jours = 168 / 7 = 24 relevés/jour
24 relevés/jour = 1 relevé/heure

Interprétation :

  • Granularité horaire : La consommation est mesurée chaque heure

  • Période : 7 jours complets (1 semaine type)

  • Précision : Suffisante pour identifier les pics de consommation

Impact métier : Permet d'analyser les patterns de consommation (jour/nuit, jour de semaine/weekend) et d'ajuster la production en conséquence.

Exemple d'analyse complémentaire :

SELECT 
    DATEPART(hour, Horodatage) as Heure,
    AVG(Consommation_kWh) as Conso_Moyenne
FROM besoins_energetiques
GROUP BY DATEPART(hour, Horodatage)
ORDER BY Heure

Insight attendu : Identifier les heures de pointe (ex: 8h-18h pour une usine)

Question 3 : Couverture photovoltaïque

Analysez la table production_solaire :

SELECT COUNT(*) as NbReleves FROM production_solaire
-- Résultat : 175 lignes

Calculez le nombre de panneaux :

175 relevés / 7 jours = 25 panneaux solaires

Vérifiez la répartition géographique :

SELECT ZoneInstallation, COUNT(*) as NbPanneaux
FROM production_solaire
GROUP BY ZoneInstallation
ORDER BY NbPanneaux DESC

Résultat attendu :

Zone Nb Panneaux % du total
Toit Nord 7 28%
Toit Sud 7 28%
Parking 6 24%

Interprétation :

  • Couverture équilibrée : Toits (56%), Parking (24%), Façade (20%)

  • Redondance géographique : Si une zone est ombragée, les autres compensent

Impact métier : Diversification des emplacements pour maximiser la production sur toute la journée (Est le matin, Sud à midi, Ouest l'après-midi).

Question 4 : Capacité éolienne et fréquence de mesure

SELECT COUNT(*) as NbReleves FROM production_eolienne

Impact métier : La haute fréquence permet d'ajuster la consommation en temps quasi-réel selon la production éolienne (ex: lancer des machines énergivores quand le vent souffle fort).

Insights métier

Insight 1 : Équilibre énergétique préliminaire

Calculez la capacité renouvelable théorique :

-- Production solaire moyenne
SELECT AVG(Production_kWh) as Prod_Solaire_Moyenne
FROM production_solaire
-- Résultat attendu : ~350 kWh/jour (25 panneaux × 14 kWh)

-- Production éolienne moyenne
SELECT AVG(Production_kWh) as Prod_Eolienne_Moyenne
FROM production_eolienne
-- Résultat attendu : ~1200 kWh/jour (5 turbines × 240 kWh)

-- Besoin énergétique quotidien
SELECT SUM(Consommation_kWh) / 7 as Conso_Quotidienne
FROM besoins_energetiques
-- Résultat attendu : ~1800 kWh/jour

Analyse de couverture :

Production renouvelable : 350 (solaire) + 1200 (éolien) = 1550 kWh/jour
Besoin énergétique : 1800 kWh/jour
Taux de couverture : (1550 / 1800) × 100 = 86%
Déficit : 1800 - 1550 = 250 kWh/jour (14%)

Interprétation :

  • 86% d'autonomie énergétique avec les sources renouvelables
  • 14% de déficit à combler (réseau traditionnel ou batteries)
  • Objectif atteint : Réduction significative de la dépendance au réseau

💡 Recommandations métier :

  1. Ajouter 5 panneaux solaires supplémentaires (+70 kWh/j) pour atteindre 90% d'autonomie
  2. Installer un système de batteries de 250 kWh pour stocker les surplus et couvrir les pics
  3. Implémenter un système de délestage intelligent pour reporter certaines charges non prioritaires

Insight 2 : Patterns temporels de consommation

Identifiez les heures de pointe :

SELECT 
    DATEPART(hour, Horodatage) as Heure,
    AVG(Consommation_kWh) as Conso_Moyenne,
    MAX(Consommation_kWh) as Conso_Max
FROM besoins_energetiques
GROUP BY DATEPART(hour, Horodatage)
ORDER BY Conso_Moyenne DESC

Résultat attendu (heures de pointe) :

Heure Conso Moyenne Conso Max
14h 95 kWh 110 kWh
15h 92 kWh 105 kWh
10h 88 kWh 100 kWh

Interprétation :

  • Pic de consommation : 14h-15h (heures de production maximale de l'usine)

  • Coïncidence : Production solaire maximale également à cette période

  • Opportunité : Synchronisation naturelle production solaire / consommation

Recommandations métier :

  • Optimiser : Lancer les processus énergivores entre 12h-16h (solaire au max)

  • Différer : Recharger les batteries et préchauffer les équipements tôt le matin (éolien nocturne)

  • Éviter : Ne pas lancer de gros consommateurs entre 18h-22h (creux de production)

Insight 3 : Variabilité de la production éolienne

Analysez la stabilité :

SELECT 
    TurbineID,
    AVG(Production_kWh) as Prod_Moyenne,
    STDEV(Production_kWh) as Ecart_Type,
    MIN(Production_kWh) as Prod_Min,
    MAX(Production_kWh) as Prod_Max
FROM production_eolienne
GROUP BY TurbineID

Résultat attendu :

Turbine Moyenne Écart-type Min Max Coefficient variation
EOL-01 10 kWh 4.2 kWh 0 18 42%
EOL-02 10 kWh 4.5 kWh 0 19 45%
... ... ... ... ... ...

Interprétation :

  • Variabilité élevée : Coefficient de variation ~40-45%

  • Imprévisibilité : Production fluctue de 0 à 18-19 kWh

  • Besoin de stockage : Les batteries sont essentielles pour lisser la production

Recommandations métier :

  • Court terme : Système de batteries de 500 kWh (couvre 6h de déficit)

  • Moyen terme : Contrat de backup avec le réseau traditionnel

  • Long terme : Diversifier avec une 2ème source prévisible (hydroélectrique si possible)
