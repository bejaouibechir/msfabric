ATELIER 4 : VISUALISATION ET ANALYSE DES DONNÉES GOLD

🎯 Objectif de l'atelier

Nous avons construit un pipeline Medallion complet (Bronze → Silver → Gold) pour modéliser un parc énergétique de 6 sites français. Les données Bronze contenaient les mesures brutes de 115 200 capteurs IoT (30 jours × 15 min). Elles ont été nettoyées (Silver) et agrégées (Gold) pour produire des tables analytiques prêtes à la décision.

Cet atelier final franchit la dernière étape : transformer ces tables Gold en visualisations intelligentes qui racontent l'histoire des données. Nous adopterons une double approche pédagogique : d'abord Python (Matplotlib/Seaborn) pour construire des graphiques sur mesure et comprendre finement les données, puis Power BI pour créer un tableau de bord interactif et partageable avec les métiers. Cette progression montre comment un data scientist passe du prototype exploratoire au produit analytique robuste.

PARTIE 1 : VISUALISATION AVEC PYTHON (Matplotlib / Seaborn)

🛠️ Prérequis

  1. Créer le notebook : Dans votre workspace Microsoft Fabric, créez un nouveau Notebook nommé NB_04_Visualisation
  2. Configurer le Lakehouse : Définissez Lakehouse_gold comme Lakehouse par défaut du notebook (section "⚙️ Lakehouse" du notebook)
  3. Vérifier les tables Gold : Via l'Explorateur du Lakehouse, assurez-vous que les 6 tables sont présentes :
    - gold.daily_consumption_by_site
    - gold.site_kpis
    - gold.consumption_by_site_type
    - gold.curtailment_opportunities
    - gold.monthly_consumption_pivot
    - gold.active_alerts
  4. Runtime : Assurez-vous que vous avez un runtime PySpark actif (environnement Fabric par défaut suffit)

📝 Cellule 0 : Configuration et chargement des données

🔍 Avant d'exécuter : Cette cellule initialise tous les paramètres visuels (polices, couleurs, thème) et charge les 5 tables Gold dans des DataFrames pandas. Elle valide que toutes les données sont disponibles.

📝 Cellule 1 : VIZ 1 — Évolution temporelle de la consommation par site

🔍 Avant d'exécuter : Cette visualisation montre les tendances sur 30 jours pour les 6 sites, regroupés par type (Industrie, Commercial, Résidentiel). Elle révèle les patterns quotidiens et les variations de charge.

Intérêt métier : Comprendre si les sites suivent des patterns prévisibles et identifier les écarts inhabituels. Par exemple, on observe généralement une consommation stable en industrie, un pic le matin/soir en commercial, et une oscillation jour/nuit en résidentiel.

💻 Code :

fig, axes = plt.subplots(3, 1, figsize=(14, 12), sharex=True)

site_groups = {
    'Industrie': ['SITE_IND_001', 'SITE_IND_002'],
    'Commercial': ['SITE_COM_001', 'SITE_COM_002'],
    'Résidentiel': ['SITE_RES_001', 'SITE_RES_002']
}

for ax, (site_type, sites) in zip(axes, site_groups.items()):
    for site in sites:
        data = df_daily[df_daily['site_id'] == site].sort_values('date')
        ax.plot(data['date'], data['avg_consumption_mw'],
                color=SITE_COLORS[site], label=site, linewidth=1.8, alpha=0.9)
        ax.fill_between(data['date'], data['avg_consumption_mw'],
                        alpha=0.08, color=SITE_COLORS[site])

    ax.set_title(f'Sites {site_type}', fontsize=12, fontweight='bold', pad=8)
    ax.set_ylabel('Consommation (MW)', fontsize=10)
    ax.legend(loc='upper right', fontsize=9)
    ax.xaxis.set_major_formatter(mdates.DateFormatter('%d/%m'))
    ax.xaxis.set_major_locator(mdates.WeekdayLocator(interval=1))

axes[-1].set_xlabel('Date', fontsize=10)
fig.suptitle('Évolution de la consommation électrique par site (30 jours)',
             fontsize=14, fontweight='bold', y=1.01)
plt.tight_layout()
plt.savefig('/tmp/viz1_evolution_temporelle.png', dpi=150, bbox_inches='tight')
plt.show()
print("✅ Viz 1 générée : évolution temporelle")

📤 Résultat attendu : Trois sous-graphiques superposés (un par type de site) montrant la courbe de consommation journalière lissée. Les zones colorées sous les courbes aident à comparer visuellement les magnitudes.

💡 Interprétation :

  • Industrie : Consommation stable (charge de base continue), peu de variation jour/nuit
  • Commercial : Pics marqués le jour (8h-18h), creux la nuit
  • Résidentiel : Oscillation jour/nuit nette, pics matinal et soirée

Ces patterns sont essentiels pour la prédiction (les modèles apprennent ces cycles) et l'optimisation d'effacement (on peut réduire en creux, moins utile à la pointe).

📝 Cellule 2 : VIZ 2 — Tableau de bord KPIs comparatif

🔍 Avant d'exécuter : Cette visualisation synthétise 3 KPIs clés pour les 6 sites en un seul graphique : taux de charge, taux d'anomalies, et erreur de prédiction. Elle permet une comparaison rapide de la performance opérationnelle.

Intérêt métier : Un site avec un taux de charge élevé mais une prédiction fiable est un bon candidat pour les contrats d'effacement. Un taux d'anomalies élevé signale des dysfonctionnements de capteur ou des événements imprévus.

💻 Code :

fig, axes = plt.subplots(1, 3, figsize=(16, 6))

<a id="kpi-1-taux-de-charge"></a>

df_kpis_sorted = df_kpis.sort_values('load_factor_pct', ascending=True)

📤 Résultat attendu : Trois histogrammes horizontaux côte à côte, chaque site coloré selon son type. Les valeurs numériques sont affichées à côté de chaque barre, avec une ligne pointillée grise indiquant la moyenne globale.

💡 Interprétation :

  • Taux de charge : Sites industriels = 60-80% (charge stable), commerciaux = 30-50% (pics ponctuels), résidentiels = 40-60% (oscillation jour/nuit)
  • Taux d'anomalies : Un site > 2% signale des problèmes de data quality ou des événements rares (coupures, pics anormaux)

Ensemble, ces trois KPIs donnent une vue d'ensemble de la santé opérationnelle et de la maturité analytique du parc.

📝 Cellule 3 : VIZ 3 — Analyse prix vs consommation et opportunités d'effacement

🔍 Avant d'exécuter : Cette visualisation double axe montre (1) la corrélation entre prix spot marché et consommation, et (2) les gains potentiels d'effacement par site.

Intérêt métier : Les sites flexibles doivent réduire la consommation quand le prix est élevé. Ce graphique identifie les opportunités d'optimisation financière : quels sites peuvent économiser le plus en s'effaçant aux bonnes heures ?

💻 Code :

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(16, 6))

<a id="scatter-prix-vs-consommation-par-type"></a>
# ─── Scatter : Prix vs Consommation par type ───
for site_type, color in TYPE_COLORS.items():
    mask = df_daily['site_type'] == site_type
    ax1.scatter(df_daily[mask]['avg_price_eur_mwh'],
                df_daily[mask]['avg_consumption_mw'],
                c=color, label=site_type, alpha=0.6, s=40,
                edgecolors='white', linewidth=0.3)

<a id="ligne-de-tendance-globale-regression-lineaire"></a>
# Ligne de tendance globale (régression linéaire)
z = np.polyfit(df_daily['avg_price_eur_mwh'].fillna(0),
               df_daily['avg_consumption_mw'].fillna(0), 1)
p = np.poly1d(z)
x_range = np.linspace(df_daily['avg_price_eur_mwh'].min(),
                      df_daily['avg_price_eur_mwh'].max(), 100)
ax1.plot(x_range, p(x_range), "k--", alpha=0.4, linewidth=1.5, label='Tendance')

<a id="seuils-de-prix-pour-effacement"></a>
# Seuils de prix pour effacement
ax1.axvline(x=200, color='orange', linestyle=':', alpha=0.7, label='Seuil effacement partiel')
ax1.axvline(x=300, color='red', linestyle=':', alpha=0.7, label='Seuil effacement max')
ax1.set_xlabel('Prix spot moyen journalier (€/MWh)', fontsize=10)
ax1.set_ylabel('Consommation moyenne journalière (MW)', fontsize=10)
ax1.set_title('Corrélation Prix marché ↔ Consommation', fontsize=12, fontweight='bold')
ax1.legend(fontsize=9)
ax1.grid(True, alpha=0.3)

<a id="potentiel-deffacement-par-site-gains-cumules"></a>

📝 Cellule 4 : VIZ 4 — Heatmap temporelle (heure × jour de la semaine)

🔍 Avant d'exécuter : Cette visualisation recharge les données horaires depuis Silver (granularité 15 min → agrégées en heures) et crée une heatmap 24h × 7j montrant les patterns cycliques.

Intérêt métier : Identifier les heures de pointe (matin, soir), les creux (nuit), et les variations week-end vs semaine. Essentiel pour la tarification dynamique et les stratégies d'effacement.

💻 Code :

<a id="charger-les-donnees-horaires-depuis-silver"></a>
# Charger les données horaires depuis Silver
df_hourly = spark.table("Lakehouse_silver.silver.consumption_with_prices").toPandas()
df_hourly['hour'] = pd.to_datetime(df_hourly['hour'])
df_hourly['hour_of_day'] = df_hourly['hour'].dt.hour
df_hourly['day_of_week'] = df_hourly['hour'].dt.day_name()

<a id="agregation-par-heure-jour-de-semaine-moyenne-tous-sites"></a>
# Agrégation par heure × jour de semaine (moyenne tous sites)
day_order = ['Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday', 'Saturday', 'Sunday']
day_labels_fr = ['Lundi', 'Mardi', 'Mercredi', 'Jeudi', 'Vendredi', 'Samedi', 'Dimanche']

pivot = df_hourly.groupby(['day_of_week', 'hour_of_day'])['avg_consumption_mw'].mean().unstack()
pivot = pivot.reindex(day_order)

fig, ax = plt.subplots(figsize=(14, 6))
sns.heatmap(pivot, ax=ax,
            cmap='YlOrRd',
            fmt='.2f',
            annot=False,
            linewidths=0.3,
            linecolor='white',
            cbar_kws={'label': 'Consommation moyenne (MW)'})

ax.set_xticklabels([f'{h}h' for h in range(24)], fontsize=8, rotation=0)
ax.set_yticklabels(day_labels_fr, fontsize=10, rotation=0)
ax.set_xlabel('Heure de la journée', fontsize=11)
ax.set_ylabel('Jour de la semaine', fontsize=11)
ax.set_title('Patterns de consommation : Heure × Jour de la semaine\n(moyenne tous sites)',
             fontsize=13, fontweight='bold', pad=15)

<a id="annotations-des-heures-cles"></a>
# Annotations des heures clés
ax.axvline(x=8, color='navy', linewidth=2, alpha=0.5, linestyle='--')
ax.axvline(x=19, color='navy', linewidth=2, alpha=0.5, linestyle='--')
ax.text(8.2, -0.5, 'Début activité', fontsize=8, color='navy', ha='left')
ax.text(19.2, -0.5, 'Fin activité', fontsize=8, color='navy', ha='left')

plt.tight_layout()
plt.savefig('/tmp/viz4_heatmap_temporelle.png', dpi=150, bbox_inches='tight')

📤 Résultat attendu : Une matrice de 7 lignes (jours) × 24 colonnes (heures) avec gradient de couleur du jaune pâle (faible consommation) au rouge foncé (forte consommation).

💡 Interprétation :

  • Zones rouges : Heures 8-19 en semaine (pic activité), très prononcé lundi-vendredi
  • Zones blanches/jaunes : Nuits (23h-7h) et samedi-dimanche (baisse générale)
  • Transition : Rampes marquées 7h-8h (start-up) et 18h-20h (shutdown)

Ces patterns sont déterministes et prédictibles → les modèles de prédiction apprennent ces cycles → précision accrue → meilleure optimisation d'effacement.

B. Créer les Mesures DAX

Les mesures sont les calculs dynamiques qui s'adaptent aux filtres du rapport.

Comment créer une mesure :

  1. Dans le panneau Données (droite), cliquez-droit sur la table daily_consumption_by_site
  2. Sélectionnez Nouvelle mesure
  3. Une barre de formule s'ouvre en haut du canvas
  4. Effacez le texte par défaut, collez la mesure, appuyez sur Entrée
  5. Répétez pour chaque mesure

💡 Bonne pratique : Créez toutes les mesures dans la même table pour les retrouver facilement.

Mesure 1 — Consommation Totale (MWh)

Consommation Totale (MWh) =
SUM('daily_consumption_by_site'[total_consumption_mwh])

Somme de la consommation sur la période et le contexte de filtrage actif (site, date, type).

Mesure 2 — Taux de Charge Moyen (%)

Taux de Charge Moyen (%) =
AVERAGE('site_kpis'[load_factor_pct])

⚠️ Cette mesure lit directement la colonne load_factor_pct déjà calculée dans site_kpis. Ne pas tenter de la recalculer depuis avg_consumption_mw / capacity_mw — ces colonnes ne sont pas accessibles dans ce contexte de filtre.

Un taux > 70 % indique une forte utilisation. En dessous de 30 %, le site est sous-exploité.

Mesure 3 — Gain Effacement Total (€)

Gain Effacement Total (€) =
CALCULATE(
    SUM('curtailment_opportunities'[potential_gain_eur]),
    'curtailment_opportunities'[potential_gain_eur] > 0
)

Somme des gains financiers sur les créneaux où l'effacement est rentable (prix spot > prix de déclenchement du site).

Mesure 4 — Nombre d'Alertes Critiques

Nb Alertes Critiques =
CALCULATE(
    COUNTROWS('active_alerts'),
    'active_alerts'[priority] = "CRITIQUE"
)

Compte le nombre d'alertes de priorité maximale. À surveiller en temps réel.

Mesure 5 — Taux Anomalies Glissant 7j (%)

Taux Anomalies Glissant 7j (%) =
VAR EndDate = MAX('daily_consumption_by_site'[date])
VAR StartDate = EndDate - 7
RETURN
DIVIDE(
    CALCULATE(
        SUM('daily_consumption_by_site'[nb_anomalies]),
        'daily_consumption_by_site'[date] >= StartDate,
        'daily_consumption_by_site'[date] <= EndDate
    ),
    CALCULATE(
        SUM('daily_consumption_by_site'[nb_measurements]),
        'daily_consumption_by_site'[date] >= StartDate,
        'daily_consumption_by_site'[date] <= EndDate
    )
) * 100

⚠️ Ne pas utiliser LastDate — c'est un mot réservé DAX. Utiliser EndDate comme ci-dessus. Ne pas utiliser DATESBETWEEN ici car la colonne date n'est pas marquée comme table de dates.

Mesure 6 — Prix Spot Moyen (€/MWh)

Prix Spot Moyen (€/MWh) =
AVERAGE('daily_consumption_by_site'[avg_price_eur_mwh])

Mesure 7 — Erreur Prédiction Moyenne (%)

Erreur Prédiction Moyenne (%) =
DIVIDE(
    AVERAGE('daily_consumption_by_site'[avg_prediction_error_mw]),
    AVERAGE('daily_consumption_by_site'[avg_consumption_mw])
) * 100

Page "Alertes" — pré-filtrer sur CRITIQUE et HAUTE

  1. Sur la page Alertes, dans Filtres sur cette page
  2. Glissez active_alerts[priority]
  3. Cochez CRITIQUE et HAUTE
  4. Masquez le filtre (icône œil) — l'utilisateur voit un bouton bascule pour inclure MOYENNE si besoin

Niveau Visuel — s'applique à un seul visuel

Visual "Gains par site" — exclure les gains nuls

  1. Cliquez sur le visuel des barres de gains pour le sélectionner
  2. Dans Filtres → section Filtres sur ce visuel
  3. Glissez curtailment_opportunities[potential_gain_eur]
  4. Type de filtre : Filtrage avancé → est supérieur à → 0
  5. Cliquez Appliquer le filtre

Visual "Alertes histogramme" — exclure le type "Autre"

  1. Sélectionnez le visuel histogramme des alertes
  2. Dans Filtres sur ce visuel, glissez active_alerts[alert_type]
  3. Type de filtre : Filtrage de base → décochez uniquement Autre
  4. Cliquez Appliquer le filtre

E. Sauvegarder et partager

  1. Cliquez sur l'icône Enregistrer (disquette, en haut à gauche) ou Ctrl+S
  2. Nommez le rapport : Parc_Energetique_Dashboard
  3. Le rapport est automatiquement accessible à tous les membres du workspace
  4. Pour partager avec quelqu'un hors du workspace : Fichier → Partager → saisissez l'adresse email
