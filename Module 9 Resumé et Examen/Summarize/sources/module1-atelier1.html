Atelier Dataflow Gen2 - Harmonisation des Données d'Énergies Renouvelables

📌 Introduction

Contexte

Vous êtes data engineer chez GreenEnergy France, un opérateur multi-énergies qui gère :

  • 4 parcs solaires (Paris, Lyon, Marseille, Bordeaux)
  • 5 parcs éoliens (Normandie, Bretagne, Picardie, Pays de la Loire, Centre)
  • 3 centrales hydrauliques (Rhône, Alpes, Pyrénées)

Objectif de l'atelier : Créer un pipeline automatisé pour harmoniser les données hétérogènes et alimenter un dashboard de monitoring unifié.

⚠️ Problématique

3 problèmes critiques

1. Silos de données incompatibles

  • Schémas différents (parc_id vs parc_code vs PlantID)
  • Formats de dates multiples
  • Unités hétérogènes (kWh vs MWh)
  • Impact : 2-3 heures/jour de préparation manuelle dans Excel

2. Qualité de données médiocre

  • Doublons → Surestimation de 1,268 MWh = 190,200 € d'erreur potentielle
  • Valeurs manquantes → Calculs de moyennes faussés
  • Codes erreur → Production négative comptabilisée

3. Absence d'orchestration

  • Processus manuel : données disponibles à 11h30 (vs arrivée à 6h00)
  • Pas de planification automatique
  • Pas de contexte métier (météo, maintenance)

ÉTAPE 1 : Créer le Dataflow Gen2

1.1 Initialisation

  1. Workspace → + New → Dataflow Gen2
  2. Nom : DF_Harmonisation_Production_Renouvelable

1.2 Ingestion des 4 sources

  1. Get data → OneLake data hub
  2. Naviguer vers : Lakehouse → Files → data_renewable
  3. Sélectionner les 4 fichiers CSV :
    - solaire_2025.csv
    - eolien_2025.csv
    - hydro_2025.csv
    - calendrier_meteo_maintenance.csv
  4. Create → Power Query Editor s'ouvre

ÉTAPE 2 : Nettoyage des données

2.1 Requête solaire_2025

Actions à effectuer :

  1. Transform → Detect Data Type (types automatiques)

  2. Home → Remove Rows → Remove Errors (sur production_kwh)

  3. Home → Filter Rows → production_kwh ≠ -888

  4. Home → Remove Duplicates (sélectionner timestamp + parc_id)

  5. Transform → Rename : timestamp → date

  6. Transform → Data Type : date → Date (sans heure)

  7. Add Column → Custom Column :

Nom : rendement_pctFormule : if [irradiation_kwh_m2] > 0 then ([production_kwh] / [irradiation_kwh_m2]) * 100 else null

Résultat : 1,460 → 1,370 lignes (-6% de données invalides)

2.2 Requête eolien_2025

Actions :

  1. Home → Remove Duplicates (toutes les colonnes)

  2. Home → Filter Rows → etat ≠ "Duplicate"

  3. Add Column → Custom Column :

Nom : production_kwhFormule : [prod_mwh] * 1000

  1. Transform → Rename : parc_code → parc_id

  2. Add Column → Custom Column :

Nom : typeFormule : "eolien"

Résultat : 1,975 → 1,770 lignes (-10% de doublons)

2.3 Requête hydro_2025

Actions :

  1. Sélectionner colonne PlantID → Transform → Replace Values :
  • Chercher : -var
  • Remplacer : (vide)

  1. Transform → Data Type → Date (pour ReadingDate)

  2. Home → Remove Duplicates (ReadingDate + PlantID)

  3. Transform → Rename :

  • ReadingDate → date
  • PlantID → parc_id
  • Production_kWh → production_kwh
  1. Add Column → Custom Column :

Nom : typeFormule : "hydro"

Résultat : 2,190 → 1,095 lignes (-50% normal : fusion des variantes)

2.4 Requête calendrier_meteo_maintenance

Actions :

  1. Transform → Detect Data Type (automatique)

Aucun nettoyage nécessaire (données propres).

ÉTAPE 3 : Fusion et enrichissement

3.1 Fusionner les 3 sources énergétiques

  1. Home → Append Queries → Append Queries as New
  2. Sélectionner :
    - solaire_2025
    - eolien_2025
    - hydro_2025
  3. Nom : production_all_types

Résultat : Table unifiée avec schéma harmonisé (date, parc_id, type, production_kwh)

3.2 Enrichir avec météo/calendrier

  1. Sélectionner production_all_types
  2. Home → Merge Queries → Merge Queries as New
  3. Configuration :
    - Table gauche : production_all_types
    - Table droite : calendrier_meteo_maintenance
    - Colonnes : date = date
    - Join : Left Outer
  4. Nom : production_enrichie
  5. Cliquer sur l'icône ⇄ → Sélectionner :
    - weekend
    - maintenance
    - pluie_mm
    - vent_mps (renommer en vent_mps_meteo)
    - jour
    - mois

3.3 Colonnes calculées finales

Add Column → Custom Column (répéter 3 fois) :

1. Production ajustée :

Nom : production_kwh_ajustee
Formule : if [maintenance] = 1 then null else [production_kwh]

2. Capacité nominale :

Nom : capacite_nominale_kwh
Formule : if [type] = "solaire" then 5000 
          else if [type] = "eolien" then 10000 
          else if [type] = "hydro" then 20000 
          else null

3. Facteur de charge :

Nom : facteur_charge_pct
Formule : if [capacite_nominale_kwh] > 0 
          then ([production_kwh] / [capacite_nominale_kwh]) * 100 
          else null

ÉTAPE 6 : Validation des données

Dans le Lakehouse :

  1. Ouvrir LH_Energies_Renouvelables
  2. Tables → production_energies_renouvelables
  3. SQL analytics endpoint → New SQL query

Requête de validation :

-- Vérifier le nombre de lignes par type
SELECT 
    type,
    COUNT(*) as nb_lignes,
    MIN(date) as date_min,
    MAX(date) as date_max
FROM production_energies_renouvelables
GROUP BY type
ORDER BY type;

-- Résultat attendu :
-- eolien  | 1770 | 2025-01-01 | 2025-12-31
-- hydro   | 1095 | 2025-01-01 | 2025-12-31
-- solaire | 1370 | 2025-01-01 | 2025-12-31

Vérifier l'absence de doublons :

SELECT date, parc_id, COUNT(*) as nb
FROM production_energies_renouvelables
GROUP BY date, parc_id
HAVING COUNT(*) > 1;

-- Résultat attendu : 0 lignes
