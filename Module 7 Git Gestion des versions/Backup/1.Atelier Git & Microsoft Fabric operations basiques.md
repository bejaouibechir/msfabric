# Atelier Git & Microsoft Fabric

**Niveau débutant · Durée : 85 min · Atelier 1/2**

---

## Objectif

À la fin de cet atelier vous savez :

- versionner votre travail avec Git
- collaborer via une Pull Request
- voir vos changements reflétés dans Microsoft Fabric

---

## Prérequis

Le formateur a préparé pour vous :

```
✓ Un compte Azure DevOps actif
✓ Un repo fabric-lab accessible
✓ Un workspace Fabric-Lab-Dev accessible
✓ Git installé sur votre poste
```

---

## Configuration initiale (10 min)

Ouvrez un terminal et configurez votre identité Git :

```bash
git config --global user.name "Votre Nom"
git config --global user.email "votre@email.com"
```

Clonez le repo :

```bash
git clone https://accessitmsfabric@dev.azure.com/accessitmsfabric/Fabric-CICD-Lab/_git/fabric-lab
cd fabric-lab
```

Vérifiez que tout est en ordre :

```bash
git status
git log --oneline
```

```
✓ Vous êtes sur la branche main
✓ L'historique des commits est visible
```

---

## Bloc 1 — Les gestes Git essentiels (35 min)

### 1.1 — Premier commit

Ouvrez le fichier `README.md` et ajoutez une ligne :

```
Participant : Votre Nom — atelier Git Fabric
```

Sauvegardez puis dans le terminal :

```bash
# Vérifier ce qui a changé
git status
git diff

# Stager le fichier
git add README.md

# Vérifier ce qui est stagé
git status

# Commiter
git commit -m "docs: ajout nom participant dans README"

# Vérifier l'historique
git log --oneline
```

```
✓ Un nouveau commit apparaît dans l'historique
```

---

### 1.2 — Le stash

Simulez une interruption — vous êtes en train de travailler et devez mettre de côté vos modifications non terminées.

Ajoutez une ligne dans `README.md` sans commiter :

```
Travail en cours...
```

Puis mettez de côté :

```bash
# Mettre de côté
git stash

# Vérifier que le fichier est revenu à l'état précédent
git status
cat README.md

# Restaurer votre travail
git stash pop

# Vérifier que la modification est revenue
cat README.md
```

```
✓ Le stash met de côté sans commiter
✓ Le stash pop restaure exactement où vous en étiez
```

---

### 1.3 — Branche feature

Vous allez maintenant travailler en isolation sur une nouvelle fonctionnalité :

```bash
# Créer et basculer sur une nouvelle branche
git checkout -b feature/mon-notebook

# Vérifier sur quelle branche vous êtes
git branch
```

Ouvrez `README.md` et ajoutez :

```
Feature : ajout notebook transformation données
```

Sauvegardez puis :

```bash
git add README.md
git commit -m "feat: description notebook transformation"

# Pousser la branche vers Azure DevOps
git push origin feature/mon-notebook
```

```
✓ La branche feature/mon-notebook est visible dans Azure DevOps
✓ Repos → Branches → feature/mon-notebook apparaît
```

## Bloc 2 — Pull Request et collaboration (30 min)

### 2.1 — Ouvrir une Pull Request

**Azure DevOps → Repos → Pull Requests → New Pull Request**

```
Source branch : feature/mon-notebook
Target branch : main
Titre         : feat: ajout notebook transformation données
Description   : Ajout de la description du notebook dans le README
Reviewers     : ajouter le formateur
```

Cliquez **Create**.

```
✓ La PR est créée et visible
✓ Le formateur reçoit une notification
```

---

### 2.2 — Review (rôle formateur)

Le formateur va :

- lire vos changements dans l'onglet **Files**
- ajouter un commentaire sur une ligne
- vous demander une correction

---

### 2.3 — Répondre à la review

Vous recevez un commentaire du formateur. Faites la correction demandée :

```bash
# Vous êtes toujours sur feature/mon-notebook
# Faites la modification demandée dans README.md

git add README.md
git commit -m "fix: correction suite review formateur"
git push origin feature/mon-notebook
```

Retournez dans Azure DevOps et **répondez au commentaire** du formateur puis cliquez **Resolve**.

```
✓ Le nouveau commit apparaît dans la PR
✓ Le commentaire est résolu
```

---

### 2.4 — Merge vers main

Le formateur approuve la PR.

Vous cliquez **Complete → Squash commit → Complete merge**.

```bash
# Revenez sur main et récupérez les changements
git checkout main
git pull origin main

# Vérifiez que votre commit est bien dans main
git log --oneline
```

```
✓ La branche main contient votre travail
✓ La branche feature est automatiquement supprimée
```

---

## Bloc 3 — Observer la synchro Fabric (10 min)

**Fabric Portal → Workspace Fabric-Lab-Dev**

```
✓ Le statut Git en haut à droite indique "Synced"
✓ Vos modifications sont reflétées dans le workspace
✓ Les notebooks et artefacts sont à jour
```

> C'est ici que Fabric prend le relais — il exécute vos notebooks, pipelines et dataflows sur la base du code que vous venez de merger.
