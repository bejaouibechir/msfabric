# Atelier : Environnements dans les Notebooks

## Pourquoi les Environnements ?

Un Environnement Fabric centralise les bibliothèques Python et la configuration Spark, et les partage entre tous les notebooks du workspace.

Sans environnement, chaque notebook doit installer ses bibliothèques au démarrage :

```python
# ❌ Mauvaise pratique — installation répétée dans chaque notebook
%pip install plotly scikit-learn
```

Avec un Environnement :

- les bibliothèques sont **installées une seule fois**
- elles sont **partagées** entre tous les notebooks du workspace
- la configuration Spark est **centralisée**
- l'environnement est **versionnable** et déployable via CI/CD

---

## Partie 1 — Créer l'Environnement

1. Dans le workspace, cliquer **+ New item**
2. Rechercher et sélectionner **Environment**
3. Nommer l'environnement : **`env_data_science`**
4. Cliquer **Create**

---

## Partie 2 — Découvrir le menu de l'Environnement

L'interface se compose de trois sections dans le menu de gauche :

### Libraries

| Sous-section              | Rôle                                                                                                           |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Built-in**              | Bibliothèques pré-installées par Fabric (non modifiables). Ex : `plotly 5.22.0` est déjà disponible par défaut |
| **External repositories** | Ajouter des bibliothèques depuis PyPI (pip)                                                                    |
| **Custom**                | Uploader des packages custom (fichiers `.whl` ou `.jar`)                                                       |

### Spark compute

| Sous-section         | Rôle                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------ |
| **Acceleration**     | Activer le **Native execution engine** pour accélérer les jobs Spark                       |
| **Compute**          | Configurer le pool Spark : taille des nœuds, mémoire driver/executor, allocation dynamique |
| **Spark properties** | Ajouter des propriétés Spark custom (ex. `spark.sql.shuffle.partitions`)                   |

### Storage

| Sous-section  | Rôle                                                                                                                       |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Resources** | Uploader des fichiers (config, certificats, données de référence) disponibles dans tous les notebooks de cet environnement |

---

## Partie 3 — Vérifier les bibliothèques Built-in

1. Cliquer **Built-in** dans le menu gauche
2. Sélectionner l'onglet **Python**
3. Rechercher `plotly` dans la barre de recherche

**Ce que vous devez voir à l'écran** :

- `plotly 5.22.0` (ou version similaire) déjà disponible
- ces bibliothèques sont présentes dans **tous** les environnements Fabric sans rien installer

> 💡 **Astuce** : avant d'ajouter une bibliothèque via External repositories, vérifier dans Built-in qu'elle n'est pas déjà disponible.

---

## Partie 4 — Ajouter des bibliothèques depuis PyPI

1. Cliquer **External repositories** dans le menu gauche
2. Deux modes sont disponibles :
   - **Full mode** : résolution complète des dépendances (recommandé, plus sûr)
   - **Quick mode** : plus rapide, moins de vérifications
3. Rester en **Full mode**
4. Cliquer le bouton **+ Add library** → sélectionner **Add library from public repository**
5. Saisir `scikit-learn` → valider
6. Pour ajouter une **deuxième bibliothèque**, cliquer à nouveau sur **+ Add library** → **Add library from public repository**
7. Saisir `great-expectations` → valider

| Bibliothèque         | Usage               |
| -------------------- | ------------------- |
| `scikit-learn`       | Machine learning    |
| `great-expectations` | Qualité des données |

> 💡 **Note** : le bouton **+ Add library** propose deux options — **public repository** (PyPI) ou **private repository** (feed privé Azure Artifacts ou autre). Pour les bibliothèques standards, toujours choisir **public repository**.

**Ce que vous devez voir à l'écran** :

- les bibliothèques listées avec leur version résolue

### Alternative — Via un fichier requirements.txt

1. Créer localement un fichier `requirements.txt` :

```text
scikit-learn
great-expectations
```

2. Cliquer **Add from .yml** ou uploader directement le fichier
3. Fabric résout automatiquement les versions compatibles

---

## Partie 5 — Configurer Spark

### 5.1 — Compute

1. Cliquer **Compute** dans le menu gauche
2. Observer les paramètres par défaut du **Starter Pool** :

| Paramètre             | Valeur par défaut         |
| --------------------- | ------------------------- |
| Node family           | Auto (Memory optimized)   |
| Node size             | Medium                    |
| Spark driver core     | 8                         |
| Spark driver memory   | 56 GB                     |
| Spark executor core   | 8                         |
| Spark executor memory | 56 GB                     |
| Dynamic allocation    | Activée (1 à 9 executors) |

> 💡 Pour un atelier sur de petits volumes, ces valeurs par défaut sont suffisantes. Ne pas modifier sauf besoin spécifique.

### 5.2 — Spark properties

1. Cliquer **Spark properties** dans le menu gauche
2. Cliquer **+ Add**
3. Renseigner :

| Property name                  | Value |
| ------------------------------ | ----- |
| `spark.sql.shuffle.partitions` | `8`   |

4. Cliquer **Confirm**

> 💡 Réduire `spark.sql.shuffle.partitions` à 8 (au lieu de 200 par défaut) accélère les traitements sur de petits volumes de données.

### 5.3 — Acceleration

1. Cliquer **Acceleration** dans le menu gauche
2. Cocher **Enable native execution engine** si vous voulez accélérer les jobs Spark

> 💡 Le native execution engine est gratuit et sans impact sur la facturation. Il est recommandé de l'activer.

---

## Partie 6 — Publier l'Environnement

Les modifications ne sont actives qu'après publication.

1. Cliquer **Publish** en haut de la page
2. Confirmer
3. Attendre la fin de l'installation (quelques minutes)

**Ce que vous devez voir à l'écran** :

- le statut passe à **Published** ✅

⚠️ **Piège** : tant que le statut est **Publishing**, l'environnement n'est pas utilisable dans les notebooks.

---

## Partie 7 — Attacher l'Environnement à un notebook

### Option A — Manuellement dans le notebook

1. Ouvrir un notebook
2. En haut du notebook, cliquer sur le sélecteur d'environnement (à côté du Runtime)
3. Sélectionner **`env_data_science`**
4. Attendre l'initialisation de la session Spark

### Option B — Par défaut pour tout le workspace

1. Aller dans **Workspace settings** → **Data Engineering / Science**
2. Sélectionner **`env_data_science`** comme environnement par défaut
3. Cliquer **Confirm**

---

## Partie 8 — Vérifier dans le notebook

```python
import sklearn
import great_expectations as ge

print(f"Scikit-learn      : {sklearn.__version__}")
print(f"Great Expectations: {ge.__version__}")
```

**Ce que vous devez voir à l'écran** :

- les deux versions s'affichent sans erreur d'import
- `plotly` est importable sans installation car il est **Built-in**

## Récapitulatif du menu

```
env_data_science
├── Libraries
│   ├── Built-in          → bibliothèques pré-installées (lecture seule)
│   ├── External repos    → ajouter via PyPI (Full mode / Quick mode)
│   └── Custom            → uploader .whl / .jar
├── Spark compute
│   ├── Acceleration      → native execution engine
│   ├── Compute           → pool, mémoire, executors
│   └── Spark properties  → propriétés custom YAML ou manuelles
└── Storage
    └── Resources         → fichiers partagés entre notebooks
```

> 💡 **Bonne pratique CI/CD** : un environnement est un item Fabric versionnable via Git. Il peut être commité dans GitHub et promu de DEV vers PROD via un Deployment Pipeline.
